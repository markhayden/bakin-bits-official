# Google Workspace pack

Gives your agents Gmail, Calendar, Drive, Docs and Sheets through
[gog](https://gogcli.sh) (OpenClaw project, MIT), pinned and installed by Bakin
into `~/.bakin/bin`. Reads run freely; anything another person can see — a
sent mail, a calendar invite, a shared file, a Sheet edit — goes through
Bakin's approval gate first (chat: a question card; task: an approval you
decide on the board or in Discord, with per-task standing grants).

## One-time setup (you, not the agent)

gog talks to Google as you, through your own OAuth client. About five minutes:

1. Create or pick a Google Cloud project: <https://console.cloud.google.com/projectcreate>
2. Enable the APIs you use: Gmail, Calendar, Drive, Docs, Sheets (People/Contacts if you want `gog contacts`).
3. OAuth consent screen (<https://console.cloud.google.com/auth/branding>):
   - **Workspace organisation account:** choose **Internal**. No verification, no
     7-day refresh-token expiry, no 100-user cap; anyone in your org can log in.
     If your admin restricts "unconfigured third-party apps", trust this client
     in the admin console.
   - **Personal gmail.com:** choose External, add yourself as a test user, then
     **Publish app** (Audience → Publish) so refresh tokens stop expiring weekly.
4. Create a **Desktop app** OAuth client (<https://console.cloud.google.com/auth/clients>) and download its JSON.
5. Log in — this is the pack's `setup` command, shown on the Health card and in Explore until it succeeds:

   ```bash
   gog auth setup you@example.com --credentials ~/Downloads/client_secret_*.json --login
   export GOG_ACCOUNT=you@example.com     # put it in the server's environment too
   gog auth list --check --json --no-input
   ```

   `gog auth setup … --dry-run --json --no-input` shows the plan without doing anything.

Then click **Check login** (Explore → Capabilities, the runtime hub, or the
Health card) or run `bakin packages login-check google-workspace`. Readiness
turns green only when `gog auth list --check --json --no-input` reports an
account with `"valid": true` (every `gog auth` command exits 0 even when no
account is stored, so the pack's `expect` pattern — not the exit status — is
the login contract) and, when `GOG_ACCOUNT` is set, names that account.

## What the agent gets

One skill (`skills/google-workspace/SKILL.md`) with Bakin's rules — the
approval classes, the chat/task confirmation contract, the provider facts
that bite — plus gog's own skills vendored verbatim under `references/`
(regenerated by `scripts/vendor-gog-skills.ts v<gog version>` whenever the
binary pin moves; the contract test holds the two together).

## Approval classes

`gmail.send`, `calendar.write`, `drive.share`, `drive.delete`, `docs.write`,
`sheets.write`. Drafts, labels, reads, exports and `freebusy` need no approval.
